# DID Character Sheet — Source fixes (2026-11-05)

This is a **source-code update** to the existing 1.0.14 DID Character Sheet project. It is **not** a Windows installer and has **not** been run in a live Windows/Android/Supabase environment. The UnifiedReader files previously identified were removed from the source archive before these changes.

## Changes

1. **Lossless campaign roll outbox:** `campaign_roll_outbox.py` atomically records linked dice rolls in the campaign AppData folder before sending them. No 200-roll queue limit; unsent events survive application restarts and are retried with their original event IDs. Cloud acknowledgement removes the local entry only after server success. An unreadable outbox is preserved and reported rather than overwritten.
2. **Avoid campaign UI freezes:** Campaigns Hub approvals, DM admission decisions, DM campaign deletion, DM character removal, and new/edited campaign-rule saves use the existing background-job/result-queue mechanism. The older wizard's campaign-list, DM roster refresh, and character-removal operations now use worker jobs too. Stale responses are ignored and selected campaigns are preserved through asynchronous refreshes.
3. **Phone-pairing network selection:** The Mobile Companion dialog now lists available LAN adapters and lets the user choose an address to advertise to Pocket DID. Automatic selection remains the default; users can refresh the list. The server validates explicitly selected addresses.
4. **Duplicate method cleanup:** Removed the overridden copy of `_detect_rendered_die_rect` and earlier redundant recovery-file methods, leaving their effective later implementations intact.
5. **Polling:** Campaign Hub, DM Dashboard, and Party Dashboard fallback poll intervals changed from 6.5s to 20s, reducing redundant cloud reads while retaining manual Refresh and existing live updates.
6. **Regression tests:** Added durable-roll and source-cleanup tests; repaired historical tests that asserted superseded UI dimensions, pre-1.0.14 installer version, and obsolete cloud admission signatures. Main `BUILD_DID_1.0.14.ps1` now builds the current source without reapplying historical patch scripts that might overwrite these fixes.

## Safety and limitations

- Existing character saves, campaign links, account credentials, and live Supabase content were **not** changed by generating this ZIP.
- The roll outbox is stored alongside the campaign link files under the campaign application's user-data folder (normally `%APPDATA%\DID Character Sheet\campaign_roll_outbox.json`). Do **not** erase this folder when updating; it contains important local identity data and pending rolls.
- Campaign joining/publication and some less-frequent legacy dialog operations may still perform network work synchronously; a complete async conversion requires safely snapshotting Qt-owned character state and device testing. This update improves the listed high-traffic operations but does not claim that every Supabase call is nonblocking.
- Full `unittest` discovery: **300 tests ran, 0 assertion failures, 9 environment-related errors** (missing PySide6 for UI import tests, or missing separate Android/phase8 sources). Focused roll, pairing, admission, performance, 1.0.14 static, and polling tests passed. The changed Python files compile and both dashboard `app.js` files pass `node --check`.
- Please smoke-test on Windows with two campaign identities and a physical phone before shipping an installer: offline roll → restart → reconnect → verify one upload; check a VPN+Wi-Fi pairing; approve/reject a DM request; create/edit/delete campaigns; verify history and local saves; confirm live dashboard changes. These cannot be validated with the available Linux tool environment.

## Building on Windows

1. Back up your original project and `%APPDATA%\DID Character Sheet` data.
2. Extract the full ZIP or copy the files from the PATCH_ONLY ZIP to the matching paths under your DID source folder.
3. From that folder, run **`BUILD_DID_1.0.14.ps1`** with your standard Windows build prerequisites (Python/PySide6/PyInstaller, Node assets, Inno Setup). It no longer runs an old source-transforming patch as a build prerequisite.
4. **Do not rerun older `apply_...`, `patch_...`, or `BUILD_DID_114_*` repair scripts over the fixed sources** without reviewing them: they may replace functions with pre-fix versions.

Version metadata remains **1.0.14**. No installer was produced in this environment.
