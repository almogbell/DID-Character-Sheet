# DID Character Sheet 1.0.14 — Numeric Inputs and Dice Repair (2026-11-06)

This is an **additional source patch** layered on the cleaned, previously fixed
1.0.14 project. Version remains 1.0.14.

## Changes

- Replaced affected text-only QSpinBox controls with `NumericEntry` (a
  QLineEdit using QIntValidator and a compatible `value()`, `setValue()`,
  `setRange()` and `valueChanged` API). This covers Adjust Resources, inventory
  item quantities, improvement costs, dice quantities, advantage/disadvantage,
  and template numeric fields. The improvement catalog editor has a compatible
  numeric field for its two inline editors as well.
- Closed the malformed `QComboBox QAbstractItemView` stylesheet block in the
  original ChoiceInputDialog. This fixes its known QSS parsing error.
- Loaded `dice.html` and its 3D assets from a Python standard-library HTTP
  server bound to **127.0.0.1 on an ephemeral port**, rather than from `file://`.
  Modern Chromium WebEngine engines require a web origin for reliable ES
  modules and worker assets. Only `dice.html`, `d100_physics.js`,
  `d100_geometry.js`, and `dice_libs/*` are served. The server rejects requests
  for character files, catalog files, configuration, and project source files.
- Installed non-module dice functions before the 3D module runs, so early
  Python calls to `rollDicePlan`, `clearDiceDisplay`, and `hideDiceResult` do not
  raise JavaScript ReferenceErrors. One early roll is queued until the engine
  is registered. Dynamic import errors are recorded, not silently swallowed.
- If the engine fails to load, the status is sent to Python and printed in
  PowerShell with a `[Dice Roller]` prefix (when WebChannel is available).

## Verification completed

- Modified Python modules compile with Python 3.13.
- Both inline JavaScript blocks pass `node --check`.
- Standalone JavaScript test confirms the non-module dice functions exist,
  queue an early roll, and delegate to an installed implementation.
- Localhost server tests pass: dice files are served; unrelated project files
  are denied with HTTP 404.
- 3 focused unittest cases pass. GUI input tests are present but skipped here
  because PySide6 is not installed in this test environment.
- Browser-level integration was attempted but the container's Chromium has
  local navigation blocked by administrator policy. Therefore 3D rolling and
  the Qt bridge **must be verified in the Windows app**.
- The project's older general test suite has pre-existing dependency/layout
  errors and a stale Campaign UI layout assertion; this patch does not address
  those tests.

## Windows test plan

1. Close the application completely.
2. Copy the patch-only ZIP's files into the existing `current code - Copy`
   project folder (keep the existing dice_libs and other project assets).
3. From that folder, run:

   ```powershell
   .\.venv\Scripts\python.exe .\frontend_2_8.py
   ```

4. Verify every numeric input displays an initial number, accepts a new number,
   respects its range, and saves the change (test Adjust Resources and Add Item).
5. Roll a normal d6/d8 and a multi-die roll. Verify the animation and Previous
   Rolls updates. Test the physical d100 separately.
6. If rolling fails, copy the new `[Dice Roller]` messages and any `js:` lines
   from PowerShell. The messages should now identify module or engine failures
   instead of `rollDicePlan is not defined`.
7. Optionally run `python -m unittest test_did_numeric_dice_regression -v`.

**Not changed:** character formats, saved data, the RPG roll rules, campaign
sync protocol, server-side data, or the version number.
